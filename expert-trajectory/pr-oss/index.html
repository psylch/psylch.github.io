Premiere 开源项目分析：谁能帮我们拿到每一步前后的状态

看了 15 个项目，没有一个是现成的“录操作前后状态”的工具，它们几乎都是让 AI 去操控 Premiere 的 MCP，而不是记录人的操作。但拼起来够用：Adobe 官方 UXP 样例已经演示了“工程有改动 / 选中变化 / 轨道变化”这些事件的订阅，以及读片段、效果参数、关键帧、标记；leancoderkavy/premiere-pro-mcp 已经做了一个事件日志，还有大量读状态的代码可以抄。建议以官方样例为底子写一个很小的 UXP 采集面板：事件一来就把整份时间线读出来存快照，前后一比就是 L2，同时定时把 .prproj 存一份做对照。

先说清三条路

Premiere 有三套接口。UXP 是新插件接口（25.6 起正式），有 EventManager 可以订阅事件，能读轨道、片段、效果参数、关键帧、标记，是我们的主路。CEP + ExtendScript 是老接口，Adobe 已宣布要逐步淘汰，但事件更细（片段加入/移除、序列结构变化），老版本也能用，适合兜底。直接解析 .prproj：它就是 gzip 压缩的 XML，可以不进软件读，但格式没公开、只能靠反推，适合当对照而不是主数据。

AdobeDocs/uxp-premiere-pro-samples 首选底座

是什么Adobe 官方 UXP 样例，68 星，2026-10-22 仍有提交，Apache-2.0。

能拿到premiere-api 面板里有现成代码：订阅 ProjectEvent.DIRTY / OPENED / ACTIVATED / PROJECT_ITEM_SELECTION_CHANGED、SequenceEvent.ACTIVATED / SELECTION_CHANGED / CLOSED、视频/字幕轨的 TRACK / INFO / LOCK 事件；读效果链（getComponentChain）、参数和关键帧（keyframe.ts）、标记（markers.ts）；写入走 executeTransaction，可撤销。

缺口只是分功能的演示，没有“事件后全量读一遍再对比”的逻辑；事件不带改了什么，要自己比。

leancoderkavy/premiere-pro-mcp 抄代码

是什么Premiere MCP，423 星，2026-10-22 仍在提交，MIT。CEP 和 UXP 两套桥都有。

能拿到唯一一个把事件做成产品功能的：uxp-plugin/events.cjs 做了一个有上限的事件日志（默认 512 条），订阅工程/序列/轨道事件，外加吸附（SnapEvent）和 OperationCompleteEvent（片段拉到头、效果拖入）；另有带类型的效果参数、关键帧、标记、时间线结构读取。

缺口它的事件日志故意丢掉原始事件内容，也不在事件时存状态；它自己的文档也写明不保证“通用或带关键帧的效果参数值能读回来”。代码量大（436 个工具），适合按需抄读状态的函数，不适合整套拿来改。

mikechambers/adb-mcp

是什么Adobe 员工个人项目，729 星，最后提交 2026-07-08，MIT。一个 Python MCP + 一个 UXP 插件，通过本地 socket 代理通信，同时支持 PS / PR / AE / ID。

能拿到PR 部分约 30 个工具：读工程信息、加媒体、改片段起止、加几种固定效果和转场、加标记、导出帧。读效果参数只有零星几处。

缺口没有任何事件订阅，没有关键帧读取。优点是结构最简单，“插件 ↔ 本地进程”这根管子可以直接借用。之前计划“基于 adb-mcp 改”，看完源码后改为只借它的通信骨架。

hetpatel-11/Adobe_Premiere_Pro_MCP

742 星，2026-10-13，MIT。283 个工具，主力是 CEP 桥，UXP 标为实验。源码里没有订阅 Premiere 事件。对我们价值是 ExtendScript 读写时间线的大量样板。

skrfilms/premiere-mcp

0 星，2026-10-21，MIT，上面那个的分叉。卖点是“每次写入都回读确认，确认不了就报失败”，回读方式包括读状态、指纹和渲染帧。这个“回读校验”思路对我们做回放验证有参考价值，但没有事件订阅。

ayushozha/AdobePremiereProMCP

126 星，2026-10-05，MIT。Go + Rust + Python + TS，走 CEP 桥，重点是“给脚本和素材自动粗剪”，改完回读时间线。没有事件订阅，架构太重。

quadlzzz/premiere-mcp

1 星，2026-09-04，MIT。改之前先复制序列，并给 .prproj 存快照（ppro_snapshot_create），改完渲染节目监视器的帧来自检。另有 docs/api-traps.md 列了会损坏工程的 API 坑，写插件前值得读。

CaYatur/PremiereProMCP

5 星，2026-10-15，MIT。UXP 优先，CEP 只用于可编辑字幕。可作 UXP 写法参考，没有事件采集。

Adobe-CEP/Samples · PProPanel 兜底

官方 CEP 样例，1088 星，MIT。jsx/PPRO/Premiere.jsx 绑定了 onActiveSequenceStructureChanged、onActiveSequenceTrackItemAdded / Removed、onActiveSequenceSelectionChanged、onProjectChanged 等事件，比 UXP 的“工程有改动”更细，能直接区分加入和删除片段。缺点是 CEP 正在被淘汰。

docsforadobe/Types-for-Adobe

647 星，2026-05-18。ExtendScript 的 TypeScript 类型定义，写 CEP 兜底时用来查 API，本身不采集任何东西。

qmasingarbe/pymiere

474 星，最后提交 2025-03-05，GPL-3.0，作者已声明不再维护。用 Python 通过 CEP 扩展调 ExtendScript，可读轨道、片段、效果参数，没有事件。GPL 协议也不适合我们改来用。

.prproj 解析：PRPROJ-READER · otio-premiereproject · prproj-rs

分别是 27 星（2022）、14 星（2021）、4 星（2023），都已停更。都证实 .prproj 是 gzip 包着的 XML，对象之间靠 ObjectID 引用，能拿到序列、片段、入出点、帧率，效果参数基本没解析。可以当“工程文件快照”的对照，但要自己补解析。

OpenTimelineIO/otio-fcp-adapter

11 星，2026-04-08，Apache-2.0。读写 FCP7 XML，Premiere 能导出这种格式，所以能把时间线转成 OTIO。但导出要人点或脚本触发，效果参数会丢很多，只适合做最终时间线的通用格式，不适合逐步采集。

推荐：基于谁改，要补什么

以官方 uxp-premiere-pro-samples 的 premiere-api 面板为底子，写一个只做采集的小插件：订阅工程改动、选中变化和轨道事件，每来一个事件就把当前序列的轨道、片段、效果参数、关键帧、标记全量读一份存下来，前后两份一比就是这一步的 L2。读状态的函数参考 leancoderkavy 的 UXP 代码，往外传数据借 adb-mcp 的“插件 ↔ 本地进程”管子，回放时借 skrfilms 的回读校验思路。另外每隔一段时间存一份 .prproj，用来核对插件有没有漏读。

要补的三件事：①“工程有改动”事件是不是每步都会来、会不会一步来好几次，要真机实测；② 事件不说改了什么，操作名要靠前后对比加截帧推断；③ 需要 Premiere 25.6 以上的版本和 CC 订阅，还要确认 Charles 的 Mac 上装了没有。
